# BazUI for LOTRO - Developer Notes

How BazUI is put together, what the LOTRO API really does (checked in the
live client, not just the docs), how the skin and its art are made, and
what's next. Read this before changing anything.

## Layout

The repository is the `Plugins/Baz4k` folder itself: clone it there as
`Baz4k` and the game loads it; edit in place.

```
BazUI.plugin            name, version, package Baz4k.BazUI.Main, apartment BazUI
BazUI/
  Main.lua              entry point: imports, the module registry, /bazui, unload
  Log.lua               BazUI's log, BazUI.Guard, /bazui dump
  Settings.lua          account-wide settings (defaults + load/save/autosave)
  Scaling.lua           follows the Global UI scale; per-window size factors
  Accent.lua            gold or grey: golds are bound to it, art greyed by Grayscale blend;
                        build_skin.py greys the skin's gold to match
  Events.lua            one handler per game event, fanned out (see Rules)
  Layout.lua            drag BazUI windows in the game's layout mode (Ctrl+\)
  Grid.lua              alignment grid shown in layout mode
  Util.lua
  Options/              settings window (General, Skin, a tab per module), Form helper
  Bags/                 combined bag: categories, pins, money
  ActionBars/           BazUI-drawn bars, custom click-only bars
    make_slot_art.py    draws Art/backdrop.tga and Art/flash.tga (any OS)
    Art/                frame.tga GENERATED by Menu/make_icons.swift; backdrop, flash
  Menu/                 BazUI's menu icons over the game's (invisible) buttons
    Geometry.lua        GENERATED by Skin/build_skin.py - where the buttons are
    Icons/              GENERATED by make_icons.swift
  UnitFrames/           player and target frames
  ClassBar/             class resources (Rune-keeper attunement so far)
  XP/                   XP bar; Levels.lua is the XP table (LOTRO Wiki)
  Skin/
    build_skin.py       builds ui/skins/BazUI for a screen size and UI scale
    make_skin_art.swift draws the skin art (Skin/Art) - macOS only
    make_chat_art.py    draws the chat window's: backing, frame, tabs (any OS)
    SkinTab.lua         the Skin settings tab
    Built.lua           GENERATED by build_skin.py - what the skin was built from
    Art/                GENERATED skin art (committed: the builder only copies it)
    Reference/          panel IDs from the U46.2 skinning pack
```

Generated files are committed because the plugin imports them (Geometry,
Built) or the builder copies them (Art) - a fresh clone works without
running the generators.

## How a module works

Each module is a table in `BazUI.Modules` (Main.lua) with `Enable()`,
`Disable()` and `BuildOptions(form)`. Enable builds on first use; Disable
hands that part of the interface back to the game. The General tab switches
modules; a module's own tab comes from `BuildOptions`. Settings live in one
account-wide table, a section per module (`BazUI.Settings.Get("Bags")`),
edited in place and saved on unload, when the settings window closes and
every two minutes. Defaults are in Settings.lua and fill in whatever a saved
file lacks.

## Rules

- **One handler per event field.** Game objects hold one function per
  event (`player.LevelChanged = f` replaces whatever was there). Never
  assign the local player's events directly: use
  `BazUI.Events.OnPlayer(event, label, handler)`, and `OnChat`,
  `OnAction`, `OnLayoutMode` for the rest.
- **Guard handlers.** `BazUI.Guard(label, fn)` reports an error once instead
  of every frame.
- **No code from other plugins or skins.** Looking at how they do things is
  fine; copying isn't. Game data (XP table, etc.) comes from the LOTRO Wiki.
- **Everything can be switched off** - every module, and every part of the
  skin (Skin tab). Off means the game's own version.
- **Versions** bump by one per release, not per change: `<Version>` in
  BazUI.plugin and `BazUI.Version` in Main.lua, a `## NNN` entry in
  CHANGELOG.md, commit message `Version NNN: <what changed, in a phrase>`.

## Testing and debugging

- **The log**: `Documents/The Lord of the Rings Online/PluginData/<account>/AllServers/BazUI_Log.plugindata`
  (a Lua table, last 300 lines). Loads, unloads and errors always;
  `/bazui debug` adds traces. Read it rather than copying chat.
- **`/bazui dump`** writes the live client's API tables to the log - check
  there before trusting docs or memory.
- **Reloading**: `/plugins unload BazUI` then `load` has been unreliable;
  relog to pick up Lua changes. **Skin changes need a full exit and
  relaunch** - the game reads skins only at start-up.
- **Screenshots**: the game's own Take Screenshot key saves to
  `Documents/The Lord of the Rings Online/screenshots`.
- Check Lua syntax with any Lua 5.1 `luac -p` if you have one; the real
  test is the game - watch the log.

## The LOTRO API, as the live client has it

- UI scaling enum is **`Turbine.UI.Lotro.UIScalingGroupType`** (the patch
  notes say `Turbine.UI` - wrong). Windows have SetScale/GetScale (GetScale
  is the total), SetUIScalingGroup, UIScaleChanged;
  `Turbine.UI.Display.GetUIGroupScale(group)`. Scaling.lua measures and
  corrects, so it works with the Plugin Manager's "Use Global Scaling" on
  or off.
- **GetUIGroupScale doesn't always tell the truth**: on Windows at
  3840x2160, Global 2.00 in Options, it answered 1 for `Global` (and every
  group but Radar). The plugin sees real pixels there (under CrossOver it saw
  points, so a missing 2x went unnoticed), and BazUI drew at half size.
  `/bazui scale 2` overrides it (saved as `Core.UIScale`; `auto` clears it).
- **Plugins can only hide** `LotroUIElement` Backpack1-6, Party,
  PluginsManager, Target, Vitals. Everything else (toolbar, quickslot bars,
  radar...) needs the skin.
- **No API for**: XP (BazUI reads "for a total of N XP" from Advancement
  chat), casting/inductions (the game's own cast bar is skinned instead),
  opening panels or firing actions (plugins only *receive* Action key
  presses), binding keys to plugin quickslots, drawing the minimap.
- **Quickslots**: Get/SetShortcut, SetAllowDrop, SetUseOnRightClick; a drop
  copies (BazUI clears the source itself to make a drag a move); no way to
  use one from code. `ShortcutType`: Undefined 0, Item 2, Alias 4, Emote 5,
  Skill 6, Pet 7, Hobby 9.
- **Rune-keeper**: `player:GetClassAttributes()` → `GetAttunement()` (0-20,
  10 neutral), `IsCharged()`; events AttunementChanged, IsChargedChanged.
- **Item enums**: `ItemCategory` and `ItemQuality` names are listed by
  `/bazui dump`; Bags/Categories.lua matches on names.
- `Turbine.Shell.AddCommand` returns a number, not a boolean.
- **PluginData** loads numeric keys back as numbers or strings - normalise
  (`tonumber`) before use, and don't trust `table.sort` with saved data.
- **Shrinking an image**: set the control to the art's own size,
  `SetStretchMode(1)`, then set the size you want (undocumented, widely
  used). Pin stretched controls with `AttachEdges` so they scale with the UI.
- A plugin window with a high `SetZOrder` draws over the game's own
  windows; keep overlays inside the window they decorate.
- **No live tinting of art.** Tested on Windows with a grey frame and a
  back color under every `BlendMode` (AlphaBlend, Color, Grayscale,
  Multiply, None, Normal, Overlay, Screen, Undefined), via both
  `SetBackColorBlendMode` and `SetBlendMode`: Color, Multiply and Screen do
  tint the art, but the back color fills the control's whole rectangle, so
  its see-through parts tint too; the rest either paint a solid square or do
  nothing (Grayscale greys the art). A colour for art has to be in the TGA.

## The skin

A LOTRO skin is `ui/skins/<Name>/SkinDefinition.xml`: `<PanelFile ID=...>`
trees that move, resize or hide elements, and `<Mapping ArtAssetID=...
FileName=...>` lines that swap art. Art is drawn at its own size and
**repeated** to fill a bigger element, so every replacement must be exactly
the size of the image it replaces. Pick the skin in Options › UI Settings ›
Current User Skin › Accept, then relaunch.

`Skin/build_skin.py WIDTH HEIGHT SCALE` writes the skin for a screen (left
out, it reuses the last build's). It reads BazUI's saved settings - the Skin
tab's switches and which modules are on - and writes `Menu/Geometry.lua`
and `Skin/Built.lua`. **Read its parts list every time**: a switch that was
off when it ran leaves that part out.

- **Positions** are in the game's points. Where the toolbar draws differs by
  platform (`TOOLBAR_NUDGE`, picked by `sys.platform`; scaled by the UI scale
  from `MEASURED_AT_SCALE`). Mac under CrossOver (1920x1080 at 0.9): about 51
  right and 20 below where it's told. Windows (3840x2160 at 2.0): 229 left,
  and its own Y is ignored - it always draws at the top - so the buttons are
  moved down inside it instead (`TOOLBAR_TOP_PINNED`). **To measure**: build
  with `--show-menu-buttons`, which draws the game's (normally invisible)
  menu buttons see-through magenta, relaunch, and compare them with BazUI's
  icons in a screenshot.
- **The menu bridge**: in bazui menu mode the game's menu buttons are made
  invisible but still take clicks and show tooltips; BazUI draws its icons
  over them from Geometry.lua. Dragging the Menu box in layout mode saves a
  spot that the next build uses.
- **Window art** is auto-mapped: `Skin/Art/frame_<game art name>.tga`
  replaces `<game art name>`. Everything else is listed in build_skin.py.

### Making art

`Skin/make_skin_art.swift` and `Menu/make_icons.swift` draw everything with
CoreGraphics, so they run on macOS only; their output is committed. To
change art on Windows, port the piece you need (e.g. to Python + Pillow) -
keep one palette: panel rgb(10,8,6) at ~0.9, gold rgb(176,141,72), bright
gold rgb(226,196,122), cream text, flat fills, one thin gold line, soft
shadow. TGAs are 32-bit, uncompressed, top-left origin, straight alpha.
Two such ports so far, standard library only: `ActionBars/make_slot_art.py`
(the slot backdrop and flash, in the frame's rounded shape) and
`Skin/make_chat_art.py` (the chat window's tabs and frame pieces, filled
like the action buttons' backdrop - rgb(31,28,26) at 0.45). The backing
behind the chat text is not skin art: with chat_back and every box_im piece
changed it still measured black at ~0.17 against the sky.
A piece moved to Python comes out of the Swift, so neither overwrites the
other.

### Finding and measuring game art

The art and panel layouts come from lunarwtr's *Unofficial Update 46.2
Skinning Pack* (lotrointerface.com, download 1204): the TGAs, and
`SkinDictionary.txt` with every panel's element tree. For each piece:
find its name, read its **actual image size** (the pack's size list is
sometimes wrong), and measure where its visible edges are (first bright row
or column, alpha) so the replacement's lines land in the same place.
Panel IDs are in `Skin/Reference/U46.2_panels.txt`.

When an element's name doesn't say which art it draws, the pack's
`SkinData.json` does: `panels` gives each element's `assets` (hex IDs) and
`assets` maps each ID to its name and size. That's how the blue glow on text
buttons turned out to be `TextButton_Highlight_l/_r` drawing the store's
`buynow_button_highight_l_small`/`_small` (sic).

## What's done, what's next

Done (v007): the modules above; skin parts Toolbar, Radar, Cast bar, Buffs,
Quest tracker, Windows (frames, plaques, tabs, buttons, scrollbars,
checkboxes, list headers, character panel).

Untested in game when this was written: the shared tabs/buttons/scrollbars
art, the action-bar lock (Shift to drop), the XP bar's text on the bar.
(Action-bar frames drawn inside each slot with stretch mode work - seen on
Windows.)

Next, roughly in order:

1. Item slots and the level shield (character panel, bags, vendors).
2. The character panel's round-socket buttons (Skills, Title...). Their
   icons are the menu buttons' art (skills_, reputation_, hobby_, bio_,
   pvppanel_...), which the Menu part maps to invisible.tga game-wide - so
   with the BazUI menu on they show blank, as do the radar's Housing and
   Destiny Points buttons and the mounted-combat window's Character and
   Skills buttons (SkinData.json lists every user).
3. Tooltips and the zone-name glow under the radar - art not found in the
   U46.2 pack.
4. Party frames, target buffs; class bars for other classes.
5. Keybinds: the game's keys fire its own hidden quickslots, so BazUI's
   bars and the keys can disagree. Plan: restyle the game's own bars with
   the skin (`quickslot_single_background` 35x35, `quickslot_numbers`)
   instead of drawing copies.
